# Decision 0002: Canonical glyph and generated variants

Date: 2026-08-07
Status: accepted

## Context

Web, the `ob start` workbench, and OAuth pages carry the same modern five-path
OpenBindings glyph geometry in copied files. Two use a self-theming favicon;
OAuth uses a `currentColor` inline variant. There is no canonical source or
mechanical relationship between those copies.

Repository history attributes the original and current forms to Matt Clevenger
in the project's Apache-2.0 repositories. The filled original appears in Web
history on 2026-03-30 and in `ob` history on 2026-04-15. The current nested
outline geometry appears in Web and `ob` history on 2026-06-15 and in archived
Panjir history on 2026-06-18.

## Decision

Adopt the existing nested-outline geometry as the OpenBindings glyph. Store a
presentation-neutral `currentColor` SVG as the canonical source in Design and
generate two committed variants:

- an inline `currentColor` artifact for embedding, masking, and host-controlled
  color; and
- a standalone favicon with light/dark operating-system color behavior.

Generated variants carry a provenance header and identity revision. Consumers
commit exact generated bytes until a cross-language distribution mechanism is
justified by more than this single asset family.

## Consequences

- Geometry and variants have one authoritative source.
- Consumers remain offline and build-system independent.
- A Design change still requires explicit consumer migrations; the adoption
  tracker makes that cost visible.
- The canonical SVG contains no accessibility semantics because each use owns
  its contextual accessible name.
- A future package or asset release may replace copied variants without
  changing the identity geometry or usage contract.
