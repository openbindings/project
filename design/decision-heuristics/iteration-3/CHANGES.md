# Iteration 3 close: draft 3 to draft 4

Applied findings from the five independent reviews and the separate editor
checks. The fixed draft 3 inputs remain unchanged in this directory.

- All five lenses: distinguish edit status from review status. Unflagged
  authorized choices may remain provisionally applied with dependents while
  review is pending; acceptance and landing remain separate.
- API and consistency: replace incomplete evaluator selections with explicit
  candidates awaiting comparison. Add a complete three-option lookup fixture,
  caller sequences, elimination trace, decision ledger and batch row.
- API: handle more than two options by retaining all undominated survivors at
  each priority level. Use one supported-countercase threshold consistently.
- Consistency: define a smaller surface by strict containment; incomparable
  surfaces proceed to the next fallback. Freeze option texts before comparison.
- Process and adversarial: hold changes whose shared-boundary compatibility
  depends on an inaccessible known reader. Record bounded search scope.
- Process: attach grades to their reviewed snapshots; closing changes get
  affected checks and explicit unreviewed status if the cap prevents a panel.
- Adversarial: essential work must demonstrate which authorized outcome cannot
  be achieved without the capability. A new sample covered by prior reasoning
  is a re-raise, not new evidence. High confidence cannot be obtained by citing
  a principle heading while omitting the unaccepted operational inference.
- API and consistency: correct the float32 example's demand-gate overreach and
  the TypeScript example's overbroad confidence explanation.
- Editor: propagate material medium and arbitrary dependencies; explain local
  contracts as correction targets without elevating them to semantic authority.

Accepted with limits:

- Grouped batch acceptance and existing standing authorization can cover
  named decisions; no need to repeat an approval already covering the case.
  This clarifies authorization handling without ratifying a new design rule.

Not adopted:

- Change any evaluator API based on the replay. This loop improves the
  decision procedure; incomplete original API packages remain visible.
- Treat a passing prior snapshot as grading a materially changed final one.
  A new panel reviews draft 4 under the unchanged charter.
